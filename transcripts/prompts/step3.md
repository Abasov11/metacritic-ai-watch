Шаг 3 — веб-интерфейс. Для вёрстки и UX используй скилл `/ui-ux-pro-max` (установлен), для кода — `/ponytail`.

Что нужно (FastAPI + Jinja2 + HTMX, без сборки фронта, один css-файл, тёмная тема по умолчанию в духе игрового каталога, аккуратно и без излишеств):
1. `GET /` — список игр: обложка, название, разработчик, дата выхода, бейджи платформ с Metascore/Userscore (цвет как на Metacritic: зелёный ≥75, жёлтый 50–74, красный <50), «лучший» metascore крупно. Панель: поиск по названию (HTMX, live), фильтр по платформам (мультивыбор, чекбоксы), сортировка (Metascore ↓/↑, Userscore ↓/↑, дата добавления). Пагинация по 24. Состояние фильтров — в query-string, чтобы ссылку можно было переслать.
2. `GET /game/{slug}` — карточка: обложка, название, разработчик/издатель, дата выхода, жанры, описание, ссылка на видео (если youtube — встроить плеер, иначе ссылка), таблица платформ с обоими счётами, ссылка на Metacritic, два блока резюме («Критики», «Игроки»): нравится / не нравится / вывод, с пометкой модели и времени обновления; если резюме ещё нет — честная заглушка «ещё не обработано». Блок «Похожие игры» (из `similar.py`): обложка + название, клик ведёт на карточку. Внизу — раскрывающийся список исходных отзывов (по 10 каждого вида).
3. `GET /api/games` (JSON, те же фильтры) и `GET /api/games/{slug}` — для проверки curl'ом и на будущее.
4. Приложение `app/main.py`: lifespan запускает планировщик из шага 2; `GET /healthz` отдаёт `{status, games, last_run}`.
5. Тесты через `TestClient` на seed-данных в временной SQLite: список, фильтр по платформе, поиск, сортировка, карточка, 404, похожие игры в карточке.
6. Живая проверка: подними `uvicorn app.main:app --port 8010`, дерни curl'ом `/`, `/game/<slug>`, `/api/games?platform=PC&sort=metascore_desc&q=…`, `/healthz`; приведи коды ответов и по 10 строк тела. Сервер после проверки останови.

Коммить по частям. В конце — отчёт: сделано / проверено запуском / не получилось.
