```
no subtitles for ufBI999BKyU (DownloadError: ... 'ru': HTTP Error 429 ...)
третья запись: no captions for this video; whisper skipped
```

Правки:
1. **Язык субтитров.** Сейчас запрашиваются `en` и `ru` — русские для англоязычного ролика это автоперевод, лишний запрос к YouTube и именно он получил 429, после чего вся стадия провалилась, хотя английские субтитры могли быть. Сделай так: сначала выяснить доступные дорожки из `info` (`subtitles` / `automatic_captions`), взять ОДНУ: ручные `en` → авто `en` → ручные/авто `ru` → любая первая доступная (LLM переведёт), и скачивать только её. Ошибка загрузки одной дорожки не должна ронять всю стадию — попробовать следующую.
2. **429 и вежливость.** На 429/5xx от YouTube — пауза с backoff (например 15, 45, 120 с, не больше 3 попыток в пределах бюджета `YOUTUBE_TIMEOUT`), между роликами внутри одного обхода/пересчёта — пауза `YOUTUBE_DELAY` (по умолчанию 5 с). Если после попыток всё равно 429 — записать причину коротко («YouTube: слишком много запросов, повтор в следующем обходе») и считать запись не свежей, чтобы следующий обход попробовал снова.
3. **Файл кук использует только сервис.** yt-dlp переписывает cookiefile обновлёнными куками после каждого запуска; два процесса с одним файлом (или файл + браузер) ломают сессию. В README это уже описано частично — добавь явно: не запускать `--refresh-letsplays` параллельно с работающим сервисом или останавливать сервис на время; а в коде — межпроцессный замок на файл кук (`fcntl.flock` на `<cookies>.lock`) вокруг каждого вызова yt-dlp, чтобы CLI и сервис не ходили в YouTube одновременно.
4. Тесты без сети: выбор дорожки по приоритету, падение одной дорожки → следующая, backoff на 429 (время замокать), замок берётся и отпускается. `ruff`, `pytest -q` — дословно.
