Шаг 12 — улучшение «похожих игр» и кнопка обновления. Код — `/ponytail`.

1. **Теги от LLM.** Сейчас похожесть считается TF-IDF по описанию, и на редких инди косинусы близки к нулю. Добавь стадию `tags`: один вызов `chat_json` на игру (дёшево, промпт по названию + жанрам + описанию + первым 5 отзывам, если есть) → строгий JSON `{genres: [..], mechanics: [..], mood: [..], setting: [..], perspective: "...", multiplayer: bool}` из ограниченного словаря (список допустимых значений задай в промпте и проверь на выходе; лишнее отбрасывай). Хранить в `games.tags` (json). Считать при первом обходе игры; при повторных — не пересчитывать, если теги есть и описание не менялось (хэш).
2. **Гибридная похожесть**: `score = 0.6 * jaccard(tags) + 0.4 * tfidf_cosine`, пропускать кандидатов с score ниже порога, чтобы блок не показывал случайных соседей; если ничего не прошло порог — блок с честной пометкой «похожих пока не нашлось». В карточке у каждой похожей игры — общие теги (2–3 штуки) как объяснение «почему похоже».
3. **Кнопка «Обновить» в карточке игры**: `POST /game/{slug}/refresh` — та же защита, что у `/monitor/run` (same-origin, не чаще раза в минуту на игру), запуск в фоне `process_game` для этой игры (карточка, отзывы, резюме, теги, летсплей), ответ 202 и HTMX-подмена блока со статусом «обновляется…», после завершения страница подтягивает свежие данные (polling блока раз в 3 с до готовности, не дольше 3 минут). В мониторинге такое обновление видно как событие.
4. Обратная засыпка: `python -m app.crawler --backfill-tags` для уже лежащих в базе игр — прогони вживую, приведи стоимость из `llm_calls` и 3 примера тегов. Пересчитай похожие для 3 игр «до/после» и покажи разницу.
5. Тесты без сети: словарь тегов фильтруется, гибридный score и порог, кнопка 202/403/429, событие в мониторе. `ruff`, `pytest -q` — дословно. Коммит по частям.
